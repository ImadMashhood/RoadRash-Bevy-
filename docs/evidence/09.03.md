# 09.03 — Dead zones, response curves and calibration preview

Complete. Implementation revision is the commit containing this receipt, code, fixtures and checkbox update. Physical controller-model acceptance is not claimed; software, actual Bevy input/rendering and the real Linux virtual-device backend were verified. Source bike handling remains open in 09.04 onward.

## Implementation

- `crates/input/src/calibration.rs`: versioned model profiles, strict validation, signed center/asymmetric travel normalization, inner/outer zones, Linear/Square/Cubic response, inversion, trigger thresholds and constant-memory center/range capture statistics.
- `crates/input/src/storage.rs`: shared bounded JSON and exclusive-temp/sync/rename persistence; binding-file behavior is preserved.
- `apps/game/src/gamepad_calibration.rs`: shared Bevy/Gilrs transport setup, transparent axis filtering and stable model keys. `input_adapter.rs` applies saved profiles before constructing the same schema-2 tick command.
- `apps/game/src/calibration_view.rs` and `src/bin/rr-calibrate.rs`: native Bevy window, live raw/output meters, 201-point exact gameplay curve, center/sweep capture, keyboard/mouse edits, model-scoped drafts, save/reset and safe session selection. Identical-model live devices cannot mix capture samples.
- `rr-input calibration ...`: real init/validate/show/set/reset/curve CLI. `rr-game --calibration FILE` selects an explicit file; otherwise an existing `local/controller-calibration.json` loads at launch. `default-run` preserves the original game command after adding the preview binary.
