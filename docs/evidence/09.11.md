# 09.11 — Focus loss and controller disconnect

Complete for the supported Linux input lifecycle. Implementation revision is the commit containing this receipt, tests and checkbox updates. This prerequisite was implemented alongside 09.02 because device switching must not leave stale held controls active. Physical USB/Bluetooth device-model acceptance remains untested.

`apps/game/src/main.rs::pause_input` runs after physical polling and before fixed updates. Loss of focus or the active controller pauses the race and clears its pending command. Regaining focus, connecting a new controller or reconnecting an old one does not resume. Resume requires an explicit configured keyboard Resume action or Start, a neutral current drive state and release of controls held at pause. The initial Pause edge cannot also resume in the same frame, including the shared P/Start bindings. Paused presentation also freezes its owned previous/current visual pair, so resuming before another fixed tick cannot rewind interpolation; the focus/pause test covers that no-tick resume case. Inactive-controller removal leaves the active device running.

`rr-input::devices::InputRouter` disarms newly connected/reconnected pads until neutral. Keyboard takeover/resume does not inherit a disconnected controller's throttle; a reconnected pad held on Accelerate stays inert through keyboard resume until released and pressed again. Prior held controls on another controller cannot take over when the active one goes neutral or disappears.

Acceptance is executable in six game adapter tests, including `focus_pause_requires_neutral_controls_and_explicit_resume` and `start_pauses_once_disconnect_stays_paused_and_resume_requires_neutral`. The latter injects actual Bevy gamepad messages, tests Start pause/hold, blocks resume with throttle held even after an earlier neutral frame, disconnects, reconnects with throttle held, explicitly resumes from keyboard, verifies zero inherited throttle and then verifies a fresh release/press works. Pure router tests cover active versus inactive loss and single-frame signaling. [Native Linux backend evidence](input-device-backend.json) verifies real uinput/evdev/Gilrs disconnect/reconnect signals using temporary controllers; main-game lifecycle consumption is covered separately by the Bevy tests.

Commands and aggregate results are in [09.02](09.02.md). Focus protection and disconnect safety change neither recorded replay schema-1 hashes nor analog replay outcomes. The implementation reserves full pause menus for the later UI phase; the current window title identifies paused state and resume controls.
