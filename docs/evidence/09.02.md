# 09.02 — Keyboard and gamepad input

Complete. Implementation revision is the commit containing this receipt, source, tests, fixtures and checkbox updates. This closes the software input task; physical controller models/USB/Bluetooth hardware acceptance is not claimed. Device calibration and source handling remain open in 09.03 onward.

`rr-input::devices` supplies finite-value sanitation, Q15 steering, the fixed standard controller preset and deterministic device arbitration. The actual Bevy adapter in `apps/game/src/input_adapter.rs` polls after `InputSystems`, before fixed ticks. Both keyboard and gamepad produce the same `rr-simulation::Command`; full keyboard/right-stick input gives identical commands and simulation hashes. `bevy_gilrs` 0.20.1 / Gilrs 0.11.2 enables real controller discovery. Linux builds/CI now include `libudev-dev`.

The engine-independent router handles simultaneous keyboard input, opposing digital directions, controller connection, two-controller switching, gradual stick changes, held-on-connect quarantine, inactive-device disconnects and active-device loss. Keyboard activity wins simultaneous devices. A pad cannot acquire ownership until it reports neutral. Other held controllers cannot silently inherit throttle when the active device goes neutral or disconnects. Session-local device IDs affect arbitration only and never enter canonical simulation state.

Analog steering is a symmetric signed Q15 value (-32767..32767) in schema-2 commands. Rendering never supplies a floating-point steering delta to simulation. Digital full lock is equivalent to the corresponding full-scale axis value. Trigger pressure currently crosses a binary driving threshold; proportional throttle/braking and source physics are not claimed. Existing schema-1 digital replays retain their exact old canonical bytes, report version and SHA-256. Unsupported/mixed commands fail before mutating simulation state. [Simulation contract](../SIMULATION.md).

## Acceptance

- Eight pure device tests cover finite/invalid axes, symmetric endpoints, D-pad priority, opposed keys, triggers, neutral quarantine, keyboard priority, controller switching, held-input isolation, active/inactive disconnects, bounded/order-independent enumeration, single-frame Start edges and gradual takeover.
- Six actual game adapter/lifecycle tests include the two earlier keyboard tests and four gamepad cases. Bevy's real `InputPlugin` consumes connection, axis and button messages; the tests verify components, commands, device switches, keyboard priority, brake precedence, disconnect pause and held-on-reconnect isolation. See `apps/game/src/input_adapter.rs` and `apps/game/src/main.rs`.
- The standalone `input_probe` example uses the **real Gilrs/Linux evdev backend** and the same production adapter. The authored C helper creates two temporary uinput controllers, never keyboard/mouse devices. [Fourteen native backend checks](input-device-backend.json) pass: connect, partial stick, South button, second-device ownership, neutral isolation, active loss, analog trigger, Start edge, reconnect, partial input after reconnect, inactive loss and final active loss. Both temporary devices were removed after the check. A pre-existing neutral backend device is counted separately; it was not used to certify physical-controller behavior.
- The kernel transport's full-left endpoint differs by one Q15 count; the native assertion permits at most two counts. Some backend reconnects retain an old axis value until a fresh report arrives. The harness explicitly reports neutral before reusing the pad, and the router's neutral gate remains in force.
- [Replay matrix](input-device-replays.json): eight headless runs (schemas 1/2 × 30/60/144/irregular) and four actual Bevy source-course windows (schemas 1/2 × 30/144) preserve every corresponding checkpoint and final snapshot. These are controlled virtual presentation schedules, not hardware FPS measurements.
